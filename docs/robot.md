# Робот: xArm 7

## Коротко про руку

| Параметр | Значення |
| --- | --- |
| Модель | UFACTORY xArm 7 |
| Ступені свободи | 7 |
| Вантажопідйомність | 3.5 кг |
| Досяжність | 700 мм |
| Повторюваність | ±0.1 мм |
| Макс. швидкість TCP | 1 м/с (ми працюємо на **≤ 100 мм/с**) |
| Підключення | Ethernet до контролера (control box), статичний IP |
| SDK | [`xarm-python-sdk`](https://github.com/xArm-Developer/xArm-Python-SDK), Python 3.10+ |

Перед першим запуском перевірити в xArm Studio: версію прошивки, налаштовані TCP-офсет і вагу захвату,
безпечні межі (safety boundary).

## Що робот має вміти

Бот рухає лише **своїх воїнів**, тож усі задачі зводяться до одного примітиву:

```text
pick(точка A) → place(точка B)
```

| Дія гри | Що робить робот |
| --- | --- |
| `Recruit(clearing, n)` | n разів: запас → вільне місце в галявині |
| `Move(src, dst, n)` | n разів: воїн у `src` → вільне місце в `dst` |
| Втрати бота в бою | n разів: воїн у галявині → запас |

**Запас** — коти бота, що стоять на **планшеті фракції бота** біля дошки (у межах досяжності руки).
Планшет камера знаходить так само, як дошку, за його малюнком ([vision.md → V1](vision.md#v1-дошка-й-планшет-бота)),
а котів на ньому — детектором (заплановано). Рука бере кота з планшета й повертає туди загиблих: на намальоване місце, якщо воно є,
інакше на вільне місце в області запасу.

## Траєкторія перенесення однієї фігурки

```text
       safe_z (напр. +80 мм над столом)
  ─────●──────────────────────●─────
       │                      │
       ▼ approach_z (+20 мм)  ▼
       │ повільно             │ повільно
       ▼ grasp_z              ▼ release_z
     [pick]                 [place]
```

1. Над точкою на висоті `safe_z`, захват відкритий.
2. Повільно опуститися до `grasp_z`, закрити захват.
3. Піднятися до `safe_z` і перейти до точки place.
4. Повільно опуститися до `release_z` (на 1–2 мм вище за стіл), відкрити захват.
5. Піднятися до `safe_z`.

Орієнтація інструменту завжди «вниз». Кут повороту навколо Z підбираємо так, щоб пальці не зачіпали сусідні фігурки
(на старті кут фіксований).
Усі висоти й швидкості задаються в `config/default.yaml`.

## Захват

❓ **Рішення ще не прийняте**, це задача першого тижня. Варіанти:

| Варіант | Плюси | Мінуси |
| --- | --- | --- |
| xArm Gripper (паралельний) + **власні 3D-друковані пальці** | надійно тримає дерев'яну фігурку | потрібен простір між фігурками для пальців |
| Вакуумна присоска (xArm Vacuum Gripper) | не потрібен простір збоку | фігурка мала й неплоска, присоска може не тримати |
| Магніт + металеві шайби під фігурками | дуже надійно, просто | треба модифікувати фігурки бота (25 шт.) |

Рекомендація: почати з паралельного захвату з вузькими пальцями. Якщо фігурки стоять надто щільно,
спробувати магніт. CAD пальців лежатиме в [`hardware/`](../hardware/).

### Драйвер: три бекенди за конфігом

Поки залізо не зафіксоване, код не прив'язаний до одного гріппера. Тип береться з `config`
`robot.gripper`; усі реалізують спільний `Gripper` (`connect / disconnect / get_position /
set_position`, працює з `with`; позиція скрізь **0.0..1.0**, 0.0 — закрито, 1.0 — відкрито):

| `robot.gripper` | Що це |
| --- | --- |
| `mock` | без заліза, памʼятає позицію (розробка/тести; також коли `robot.mock: true`) |
| `ufactory` | стандартний гріппер UFACTORY xArm через `xarm-python-sdk` (тонкий адаптер 0..1 ↔ 0..`max_pulse` пульсів) |
| `somatic` | гріппер Somatic, приватний драйвер (внутрішній протокол, **не входить у репо**) |

`create_gripper(cfg)` обирає бекенд. `main` створює гріппер, під'єднує його й передає в
`Manipulator`; при будь-якому завершенні (кінець, помилка, Ctrl+C) рука йде в home, а гріппер
відкривається (відпускає фігурку, якщо тримав) і від'єднується. Збій цих кроків лише в лозі й у
статусі для оператора. Решта коду знає лише `Gripper`, тож гріппери взаємозамінні — як
`Arm`/`MockArm`. Ручна перевірка: `python scripts/gripper_control.py --set 0.25`.

Числа заліза `ufactory` — у `robot.ufactory_gripper` (`max_pulse`, `speed_rpm`, `timeout_s`).
Якщо контролер руки в помилці (зіткнення, вихід за межі безпеки), `connect()` кидає
`TemporaryError`: помилку скидає людина свідомо, напр. у xArm Studio.

## Код

```text
src/rootbot/robot/
├── arm.py         # Arm (протокол, home()), MockArm (рухи в лог), XArm (через SDK; заплановано)
├── gripper.py     # Gripper (протокол), MockGripper, UFactoryGripper (SDK); create_gripper за config
├── transforms.py  # перетворення поз і точок (камера ↔ фланець ↔ база ↔ дошка)
├── hand_eye.py    # (заплановано) hand-eye калібрування: поза камери в базі з пози фланця
├── scan.py        # оглядові пози, знімання на зупинці
└── manipulator.py # Manipulator: перенести фігурку (взяти → поставити); поки заглушка, пише задачу в лог
```

- **Увесь** код поза `robot/` працює з `Arm`, а не з SDK напряму. Так можна запускати все з `MockArm`.
- Заплановано: `Manipulator` перевіряє кожну точку перед рухом на потрапляння в дозволену зону
  (`robot.workspace_mm`, bounding box стола). Якщо точка поза зоною, кидає виняток **до** руху.
- Заплановано (`XArm`): кожен виклик SDK повертає код. Ненульовий код означає помилку: зупинка, лог, повідомлення
  оператору.

## Ручне керування

`scripts/jog_robot.py`: рух клавіатурою по X/Y/Z з кроком 1/10 мм, відкрити чи закрити захват,
вивести поточну позицію. Потрібен для калібрування й налагодження.

## Огляд і уточнення камерою

Камера на фланці ([ADR 0005](decisions/0005-camera-on-arm.md) *(з'явиться з PR про камеру на руці)*), тож рука сама обирає, звідки дивитися.

1. **Огляд.** На початку ходу рука по черзі стає в оглядові пози (`config/default.yaml` → `camera.scan_poses`,
   1–4 пози), на кожній зупиняється й знімає кадр. Детекції з усіх кадрів зводяться в одну карту фігурок у мм
   дошки, дублі на перетинах кадрів зливаються. Поки поз немає (`scan_poses: []`): один кадр з поточного місця.
2. **Уточнення перед захватом** (заплановано). Над фігуркою на висоті `look_z` (~12–15 см) ще один кадр зблизька:
   точна позиція (~1 мм), сусіди, вибір повороту пальців навколо Z, щоб пройти між фігурками.
3. **Перевірка після place** (заплановано). Кадр над місцем призначення: фігурка стоїть там, де треба.

Висоти `scan_z` (огляд) і `look_z` (кадр зблизька) з'являться в `config/default.yaml` разом із цими кроками.
Камера має лишатися на `look_z` або вище, поки під нею фігурки: вона ширша за пальці.

Код: `robot/scan.py` (пози огляду, знімання на зупинці). Заплановано: `robot/hand_eye.py` (поза камери в базі),
`vision/geometry.py` (промінь → точка на столі).
