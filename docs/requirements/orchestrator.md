# Вимоги: Orchestrator і MovePlanner

Компоненти `app`, які ведуть партію ([architecture.md → app](../architecture.md#app--точка-входу-й-оркестратор-партії)).
Код: [`app/orchestrator.py`](../../src/rootbot/app/orchestrator.py), [`app/move_planner.py`](../../src/rootbot/app/move_planner.py).
Чому дерево поведінки: [ADR 0007](../decisions/0007-behaviour-tree.md). Сигнали й статус: [operator-server.md](operator-server.md).

## Функціональні вимоги (FR)

### Партія

| ID | Вимога |
| --- | --- |
| FR-O1 | Між ходами бот чекає сигналу «Хід бота» ([`your_turn()`](operator-server.md#методи)). |
| FR-O2 | Партія закінчується, коли: хтось має `game.win_points` (30) ПО — перевіряється з огляду на початку ходу бота; або прийшов сигнал «Кінець гри» ([`end_game()`](operator-server.md#методи)). |
| FR-O3 | Ctrl+C зупиняє програму, але це **не** кінець гри: рука йде в home, програма виходить з кодом 130. |
| FR-O4 | Сигнал «Карту дано» ([`card_given()`](operator-server.md#методи)) між ходами: бот отримує ПО за рисою Poor Manual Dexterity (`game.traits.card_given_points`), рука пересуває жетон рахунку бота. |
| FR-O5 | Стан партії (`GameState`) один на всю гру й щоходу оновлюється з огляду (`GameState.update`): фігурки (лише галявин, які огляд побачив) і рахунки людей — з камери; невидимі галявини лишаються як були; свій рахунок бот веде сам; Keep — з камери, а якщо не видно, лишається попередній; знищений під час ходу людини — сигнал «Keep знято» ([`keep_removed()`](operator-server.md#методи), [AUT-13](../autonomy.md#aut-13)). |

### Хід бота

| ID | Вимога |
| --- | --- |
| FR-T1 | Початок ходу: повний огляд дошки → `BoardObservation` → `GameState`. |
| FR-T1a | Огляд (`observe_board(target)`): знімати й передавати кадри детектору (`add_frames`), поки він не побачить усю ціль; потім `detect()`; потім уточнювати (`refine`), поки детектору є що переглянути. `Scanner` сам вирішує, як дознімати. Обидва цикли разом — не більше `camera.max_rechecks` (4) переглядів; далі хід іде з найкращим, що є, а сумнівне — у лог. |
| FR-T2 | Світанок: очки за `marquise_bot.birdsong`, рука пересуває жетон рахунку. |
| FR-T3 | День: карта наказу. **Тимчасово** її вводить людина в застосунку ([`order_card()`](operator-server.md#методи)); згодом її відкриватиме й читатиме рука з камерою ([AUT-1](../autonomy.md#aut-1)). |
| FR-T4 | День іде крок за кроком: бої → рух → набір; кожен крок отримує актуальний стан. |
| FR-T5 | Стан після кожного кроку Дня перераховується з виконаних дій; після боїв — **частковий огляд** галявин боїв, бо втрати людей прибирають люди. |
| FR-T6 | Бій: **тимчасово** кубики кидає людина й вводить результат ([`dice_rolled()`](operator-server.md#методи)); згодом кидатиме рука ([AUT-2](../autonomy.md#aut-2), [AUT-3](../autonomy.md#aut-3)). Рахує `marquise_bot.resolve_battle`. |
| FR-T7 | Втрати бота (воїнів) прибирає рука в запас. Скільки знімає захисник — показується людям у статусі. Знятий Keep поки прибирають люди ([AUT-8](../autonomy.md#aut-8)). |
| FR-T8 | Карта без вартості крафту (`recruits` повертає `None`): День повторюється з наступною картою, поки в Розкладі є карти. |
| FR-T9 | Вечір: у статусі — скільки карт добрати в Розклад (`marquise_bot.evening`); добирають люди ([AUT-9](../autonomy.md#aut-9)). |
| FR-T10 | Кінець ходу: рука в home, бот знову чекає «Хід бота». |

### Збої

| ID | Вимога |
| --- | --- |
| FR-E1 | Крок ходу, що не вдався (огляд, переміщення), повторюється `orchestrator.step_retries` разів. |
| FR-E2 | Якщо повтори не допомогли: рука в home, статус «потрібна допомога» з помилкою, бот чекає людину ([AUT-7](../autonomy.md#aut-7)). Наступний «Хід бота» продовжує **той самий** крок. |
| FR-E3 | Повтор не виконує вдруге те, що вже зроблено: жодна фігурка не переноситься двічі, очки не нараховуються двічі. |

### MovePlanner

| ID | Вимога |
| --- | --- |
| FR-P1 | Перетворює дію бота на переміщення фігурок (`PieceMoveTask`): `Move` → яких котів узяти й куди поставити, `Recruit` → із запасу на вільні місця, втрати → у запас, очки → жетон по доріжці рахунку. |
| FR-P2 | Пам'ятає заплановане в цьому ході: узяте місце стає вільним, зайняте — ні. |
| FR-P3 | Якщо позиції котів не відомі, бере центр галявини (Manipulator уточнює кадром зблизька). |
| FR-P4 | Вільне місце шукає сам, з позицій усіх фігурок (`BoardObservation.positions`): найближча до центру точка в колі галявини, не ближче за `board.piece_spacing_mm` до інших фігурок. Детектор вільних місць не рахує. |

## Нефункціональні вимоги (NFR)

| ID | Вимога |
| --- | --- |
| NFR-O1 | Партія — Behaviour Tree на [`py_trees`](https://py-trees.readthedocs.io/); методи `Orchestrator`: `run()` — тикає дерево до кінця гри, `build_tree()` — збирає дерево ([ADR 0007](../decisions/0007-behaviour-tree.md)). |
| NFR-O2 | `Orchestrator` сам нічого не рахує, не розпізнає й не рухає: лише викликає `game`, `vision`, `robot`, `MovePlanner`. |
| NFR-O3 | Усі компоненти створює `main` і передає готовими. `Orchestrator` залежить від `Protocol` (`Arm`, `Camera`), а не від конкретних класів, тож мок і справжня рука взаємозамінні. |
| NFR-O4 | Працює в головному потоці; з `OperatorServer` спілкується лише через чергу сигналів і об'єкт статусу ([ADR 0006](../decisions/0006-operator-app.md)). |
| NFR-O5 | Вузол дерева не блокує надовго в очікуванні людини: повертає RUNNING, поки сигналу немає. |
| NFR-O6 | Параметри (`tick_period_s`, `step_retries`, `win_points`, параметри бота) — лише з [`config/default.yaml`](../../config/default.yaml). |
| NFR-O7 | Тести — з підставними модулями, які записують виклики; тест перевіряє порядок дій ([`tests/app/test_orchestrator.py`](../../tests/app/test_orchestrator.py)). |
| NFR-P1 | `MovePlanner` — окремий компонент `app`, тестується без `Orchestrator`. |
