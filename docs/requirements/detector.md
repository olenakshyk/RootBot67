# Вимоги: зір (Detector)

Модуль `vision` ([architecture.md → vision](../architecture.md#vision--кадри-огляду--стан-дошки)): кадри огляду → хто де стоїть.
Алгоритми й пайплайн: [vision.md](../vision.md). Хто викликає й як дознімає: [orchestrator.md → FR-T1a](orchestrator.md).

## Компоненти

```
кадри ──► Detector ─────────────────────────────────────► BoardObservation + RecheckRequest | None
            ├─ board_detector:      кадр → BoardHomography (піксель ↔ мм дошки, що видно)
            └─ PieceDetectorModel:  кадр → [PieceBox] (рамка, фракція, вид, впевненість)
```

## Функціональні вимоги (FR)

### Дошка на кадрі — `board_detector` (V1)

| ID | Вимога |
| --- | --- |
| FR-V1 | Знаходить дошку на кадрі без маркерів, за її малюнком: зіставлення ключових точок кадру з еталоном дошки → `BoardHomography`. |
| FR-V2 | `BoardHomography` переводить піксель кадру в точку дошки в мм (система координат дошки, [calibration.md](../calibration.md#системи-координат)). |
| FR-V3 | `BoardHomography` каже, яку частину дошки видно на кадрі, і чи видно галявину цілком (коло галявини з мапи всередині кадру). |
| FR-V4 | Якщо дошку не знайдено (мало збігів, вироджена гомографія), повертає «не знайдено», а не неправильну гомографію. |
| FR-V5 | Той самий механізм — для планшета фракції бота (запас котів) з окремим еталоном. |

### Фігурки — `PieceDetectorModel`

| ID | Вимога |
| --- | --- |
| FR-V10 | Інтерфейс «кадр → список `PieceBox`»: рамка в пікселях, фракція, вид фігурки (воїн, будівля, жетон, пішак, маркер рахунку, …), впевненість 0..1. |
| FR-V11 | Реалізацію (YOLO, RT-DETR, колір, …), ваги й поріг обирає конфіг; заміна моделі не змінює код `Detector`. |
| FR-V12 | Класи моделі перекладаються на фракцію й вид фігурки через таблицю в конфігу: модель з іншою схемою класів підключається без змін у коді. |

### Detector

| ID | Вимога |
| --- | --- |
| FR-V20 | Точка фігурки — точка її **основи** на площині дошки (не центр рамки), у мм дошки. |
| FR-V21 | Фігурка (воїн, будівля, жетон, пішак, Keep) належить найближчій до точки основи галявині з мапи; точка поза дошкою (планшети, запас) і маркери рахунку галявини не отримують, коти на планшеті бота — запас. |
| FR-V22 | Кілька кадрів зводяться разом: та сама фігурка з різних кадрів (той самий вид і фракція, поруч у мм) — одна фігурка. |
| FR-V23 | Три публічні кроки по черзі: `add_frames(frames, target)` → `detect()` → `refine(observation, frames)`; цикли й ліміт спроб веде `Orchestrator` (спільний ліміт `camera.max_rechecks`). |
| FR-V24 | `add_frames` — лише покриття, без моделі. Ціль — маска дошки (`BoardMask`): уся дошка, галявини (коло з мапи, розширене на `vision.clearing_margin`, 4 %) або інша маска. Повертає `RecheckRequest([RecheckReason.NOT_VISIBLE], uncovered=маска непокритого)`, поки кадри покривають менше `vision.min_coverage` (97 %) цілі, або `None`. Кадри накопичуються; новий огляд починається з `target` або першим `add_frames` після `detect()`. |
| FR-V25 | `detect()` перевіряє покриття (неповне — попередження в лог і розпізнавання з тим, що є), запускає модель один раз на всіх накопичених кадрах і повертає `BoardObservation` (галявини, які видно цілком) + один `RecheckRequest` з усіма сумнівними галявинами (причини — список `reasons` з `RecheckReason`, у такому порядку: `DISAGREE`, `LOW_CONFIDENCE`) або `None`. `refine(observation, frames)` — лише після `detect()` (інакше помилка): розпізнає нові кадри й оновлює галявини, які на них видно цілком. |
| FR-V26 | Вільних місць не рахує — лише хто де стоїть ([orchestrator.md → FR-P4](orchestrator.md)). |
| FR-V27 | Згодом: поза дошки в системі бази робота з гомографії й пози камери (`board_pose`), коли буде рука й hand-eye. |
| FR-V28 | Модель створюється один раз на старті (ваги + прогрів) і живе до кінця програми; кадри огляду йдуть у неї одним викликом. |
| FR-V29 | Keep є рівно там, де його розпізнано на галявині (`keep_clearing`); галявина Keep, яку `detect()` чи `refine()` бачить цілком без нього, означає, що Keep знищено (`keep_clearing = None`). |
| FR-V30 | Для кожної галявини, яку видно цілком, `BoardObservation` дає точки основи: `positions` — фігурок з `pieces` по фракціях (звідси рука бере фігурки бота), `occupied` — усіх фігурок на галявині будь-якої фракції й виду разом з Keep (з цього `MovePlanner` рахує вільні місця). |

## Нефункціональні вимоги (NFR)

| ID | Вимога |
| --- | --- |
| NFR-V1 | `vision` не знає про руку й правила гри: на вході кадри (і згодом пози камери), на виході — спостереження. |
| NFR-V2 | `PieceDetectorModel` — `Protocol` в окремому файлі `vision/piece_detector_model.py`; важкі залежності (torch, ultralytics) імпортуються лише в реалізації. |
| NFR-V3 | Параметри (еталон, пороги збігів, RANSAC, модель, таблиця класів) — лише з [`config/default.yaml`](../../config/default.yaml). |
| NFR-V4 | Еталони дошки й ваги моделей не в git (`data/reference/`, `models/`). |
| NFR-V5 | Тести не залежать від файлів поза git: синтетичні кадри з відомою гомографією, фейкова модель. |
| NFR-V6 | Цілі якості ([vision.md → Метрики](../vision.md#метрики)): дошку знайдено ≥ 99 % кадрів; похибка точки ≤ 5 мм; кадр ≤ 2 с. |
